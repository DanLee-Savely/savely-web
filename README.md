# 세이블리 웹사이트 (savely-web)

- 소개 사이트(`/home`) — 출시 전 가계부 앱 「세이블리」의 소개 페이지
- 기록 체험판(`/app`) — 웹에서 기록(지출 · 수입 · 상환 · 저축)을 적고 · 보고 · 고치고 · 지우고, 홈 · 달력 · 리포트로 모아 보는 체험판(아래 「기록 체험판」)
- 대화로 기록하기 — 체험판 안에서 「점심 9천원, 커피 4500원」처럼 한 문장으로 적으면 기록 초안을 만들어 주는 기록 도우미(아래 「대화로 기록하기」, OpenAI API 활용)

## 배포 URL
- 실서비스(Cloudflare Workers): https://www.savelyglobal.com/home
- 기록 체험판(Cloudflare Workers): https://www.savelyglobal.com/app — 2026-11-10 배포, 같은 Worker의 `/app*` 라우트
  - 홈 `/app` · 기록 `/app/records` · 달력 `/app/calendar` · 리포트 `/app/report`
  - 소개 사이트 히어로의 「웹에서 체험하기」(PC)로 들어가고, 체험판 왼쪽 위 로고로 소개 사이트에 돌아온다
  - 대화로 기록하기 · 기록 종류 4가지: 2026-11-26 배포. 모든 `/app` 화면 오른쪽 아래 「대화로 기록하기」 버튼으로 연다
  - 패널로 들어가는 길 강조(홈 주 버튼 · 한 줄 입력칸 · 예시 칩 · 폼의 「대화로 적기」 · `/app?chat=1`)와 소개 사이트 「대화로 기록하기」 구역: 2026-11-26 배포

**검수 결과 한눈에:** 소개 사이트는 섹션별로 시안과 비교해 차이를 고쳤다(1440 · 1280 · 1024 · 768 · 390 · 360에서 가로 스크롤 · 콘솔 오류 · 깨진 링크 0, iOS 실기기 확인). 체험판은 QA 51개(Q1~Q51 — 2026-11-26에 Q1~Q30을 다시 돌리고 기록 종류 4가지 · 대화로 기록하기 14개, 패널 밖의 입구 · 소개 사이트 새 구역 7개를 더함)를 로컬 Worker 환경에서 모두 통과했고, 점검 중 찾은 버그(삭제 확인 창이 저절로 닫힘 · 두 번 저장 · 없는 기록이 HTTP 200 · 없는 날짜에서 멈춤 · `/app?…` 522)를 고쳤다.

## 서비스 소개
세이블리(Savely)는 직접 적으며 소비를 돌아보는 가계부 앱이다(iOS · Android, 출시 전).
- **문제:** 돌아볼 틈 없이 같은 한 달이 반복된다. 결제는 터치 한 번이면 끝나고, 월말 명세서에서야 합계를 본다
- **해결:** 적고 · 마감하고 · 돌아보는 습관을 만드는 가계부 + 꾸준한 마감을 돕는 세이블리 포인트
- **기대효과:** 점검이 습관이 되면 한 달이 달라진다
- **핵심 행동:** 「출시 알림 신청」 — 이메일을 남기면 출시 소식을 먼저 받는다

- 가족 소비를 함께 돌아보고 싶은 사람

| 검사 | Vitest(도메인 · 상태 클래스 · 문장 세트, D1 쿼리는 Node 내장 SQLite) · Playwright(시안 비교 스크린샷 · QA 자동 점검) · ESLint |

- 경로: 메인은 `src/app/home/` → `/home`. basePath 없이 두어 이후 로그인 후 PC 앱(`/app` 등)을 같은 프로젝트에 이어 붙일 수 있다

## 기록 체험판 `/app`
명세 원본: `docs/spec/70-mvp-records.md` · QA 결과: `docs/spec/71-mvp-qa.md` · 시안: `docs/design/app/`

> 2026-11-26: 기록 종류가 4가지(지출 · 수입 · 상환 · 저축), 카테고리가 41종이 됐고 카테고리는 선택 사항이 됐다. 명세 `docs/spec/80-record-assistant.md`가 `70`보다 우선한다.

세이블리의 출발점인 「직접 적는다」를 웹에서 검증한다. 로그인 없이 누구나 같은 데이터를 보고 고치는 **공개 체험판**이라, 모든 화면 위에 「실제 소비 내역 · 개인정보를 적지 말라」는 안내 띠를 두고 검색에서 뺐다(noindex).

| 홈 | `/app` | 「오늘 세 번 적었어요.」(오늘 건수에 따라) · 오늘 쓴 돈과 최근 3건 · 이번 달 쓴 돈 · 수입 · 기록 · 하루 평균 · 최근 7일 지출 막대 · 이번 달 많이 쓴 곳 상위 3 |
| 달력 | `/app/calendar?month=&date=` | 월요일 시작 칸에 날짜별 지출, 달 이동(미래 달 없음), 선택한 날의 쓴 돈 · 기록 · 필수지출 건수 · 기분 집계 · 「이 날 기록 추가」(그 날짜로 등록) |
| 리포트 | `/app/report?month=` | 월 지출 · 수입 · 하루 평균 · 지난달 같은 기간 비교 · 가장 많이 쓴 곳, 주별 지출(1–7 … 29–말일, 진행 중 · 예정), 카테고리별 비율, 왜 썼고 기분은 어땠나요 · 충동 인사이트 |
| 목록 | `/app/records?page=N` | 날짜 최신순 10건씩, 이전 · 번호(최대 5개) · 다음. 빈 상태 · 로딩(회색 막대 10줄) · 불러오기 오류 + 「다시 시도」 |
| 등록 | `/app/records/new` | 구분(지출 · 수입 · 상환 · 저축) · 금액 · 날짜(필수), 카테고리(선택, 먼저 12개 + 더보기) · 내용 60자 · 메모 200자 · 결제수단 · 카드 이름(카드 결제일 때만, 20자) · 왜 썼나요 · 그때 기분 · 사진 1장(선택). 지출이 아니면 지출 전용 칸 숨김 |
| 상세 | `/app/records/[id]` | 모든 항목(빈 항목은 「—」) · 사진(원본 새 탭) · 처음 적은 시각 · 고친 시각, 「수정」 · 「삭제」(확인 창) |
| 수정 | `/app/records/[id]/edit` | 등록과 같은 폼에 기존 값, 사진 바꾸기 · 삭제 |
| 사진 | `/app/records/[id]/image` | R2에서 꺼내 전달(버킷 공개 주소 없음) |
| 없는 기록 | — | 「찾는 기록이 없어요」, HTTP 404 |

- 검증은 브라우저와 서버가 **같은 도메인 클래스**(`RecordEntry.check`)로 한다. 칸별 오류 문구, 첫 오류 칸으로 포커스, 저장 중에는 입력 잠금 · 두 번 저장 방지
- 저장 · 수정 · 삭제 뒤 알림(「기록했어요」 등 3초), 쓰기 요청 제한(IP당 1분 10회, 넘으면 「요청이 너무 많아요」)
- 홈 · 달력 · 리포트는 기록 테이블만 읽어 계산한다(`record_date BETWEEN ? AND ?` 집계). 금액 · 막대 · 비율은 **지출만**, 수입은 「수입」 줄에만(M19), 「기록 n건」은 4종 모두(K3). 카테고리를 고르지 않은 지출은 「기타」에 합친다(K5). 「오늘」 · 「이번 달」은 Asia/Seoul
- 금액 표기: 수입만 `+`와 초록, 상환은 흐린 색, 지출 · 저축은 부호 없이 기본색(K2)
- 사진은 브라우저에서 긴 변 1600px JPEG로 다시 저장해 찍은 위치(GPS) 등 EXIF를 지운 뒤 올린다. 서버는 파일 앞부분 바이트로 JPG · PNG · WEBP · 5MB 이하를 다시 확인한다
- 소개 사이트 히어로에 「웹에서 체험하기」(PC만) → `/app`

### 데이터 처리 규칙
- D1 · R2는 서버 코드에서 Cloudflare **바인딩**으로만 접근한다(`src/infrastructure/container.ts`). 브라우저에는 데이터베이스 · 버킷 주소나 키가 없다
- SQL은 바인딩 파라미터(`?1`…)만 쓴다. DB CHECK 제약은 마지막 방어선
- 「오늘」은 Asia/Seoul 기준, 날짜는 문자열 그대로 다룬다
- 로그에는 기록 id와 오류 종류만 남긴다(금액 · 내용 · 메모 금지)
- 출시 알림 D1(실제 이메일)과 **다른 데이터베이스**다

## 대화로 기록하기
명세 원본: `docs/spec/80-record-assistant.md`(v2.1) · QA 결과: `docs/spec/71-mvp-qa.md`(Q31~Q51) · 시안: `docs/design/app/`(30~58)

기록 폼은 한 건에 여러 칸을 채워야 한다. **한 문장으로 적으면 기록 초안을 만들어 주고, 사용자는 확인하고 저장만 하면 되게** 해서 입력 마찰을 줄였다. 모바일 앱의 「대화로 기록하기」와 같은 동작이다(웹은 앱의 PC 버전).

### 흐름
1. 패널을 연다 → 오른쪽 패널(너비 440, 뒤 화면을 가리지 않음). 들어가는 길은 여러 개다(명세 80 §3-3)
   - 홈: 오른쪽 위 주 버튼 「대화로 기록하기」 · 제목 아래 한 줄 입력칸(보내면 패널이 열리며 그 문장이 처리된다) · 예시 칩 3개(누르면 바로 보낸다 — 세 문장 모두 규칙만으로 처리돼 OpenAI를 부르지 않는다)
   - 기록하기 폼: 오른쪽 위 「대화로 적기」(적던 값이 있으면 버릴지 먼저 묻는다)
   - 기록 · 달력 · 리포트: 오른쪽 아래 떠 있는 버튼
   - 주소 `/app?chat=1`: 패널을 연 채로 들어온다(소개 사이트의 「웹에서 체험하기」와 「대화로 기록하기」 구역 버튼)
2. 문장을 보낸다 — 「점심 9천원, 커피 4500원」, 「어제 택시 12000원」, 「월급 300만원」
3. 초안 카드가 나온다. 카드를 눌러 고치고(수정 시트), 지출 카드는 왜 썼나요 · 그때 기분을 칩으로 고를 수 있다(선택)
4. 「n건 저장하기」 → 확인 창 → 저장 요약. 문장의 날짜마다 그 날짜로 저장된다

### 문장을 읽는 순서
위에서부터 먼저 맞는 것으로 정한다(모바일 앱과 같은 순서, 테스트로 고정).

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | 도움말 낱말(「도움말」 · 「뭐 할 수 있어」) | 「할 수 있는 일」 목록과 예시 |
| 2 | 「고정지출」 · 「고정수입」 · 「매달」 · 「매월」 | 고정지출 등록 카드 · 목록 · 삭제 확인 |
| 3 | 「○○카드」 + 「등록」 · 「추가」 | 카드 등록 카드 |
| 4 | 금액이 있다 | 기록 초안 |
| 5 | 묻는 말(「이번 달 카페 얼마」 · 「어제 뭐 썼지」) | 저장된 기록에서 센 숫자로 답한다(대화로 물어보기) |
| 6 | 그 외 | 「금액을 찾지 못했어요…」 안내 |

- 4번의 기록은 **규칙 기반 파서**(금액 · 날짜 · 낱말 사전 38개 카테고리 400개 낱말)가 먼저 읽는다. 읽지 못한 조각과, 내용은 있는데 카테고리를 찾지 못한 항목만 OpenAI로 보낸다. OpenAI가 만들거나 채운 카드에는 「AI가 정리」를 붙인다
- 1 ~ 3번과 5번은 규칙으로만 읽고 OpenAI로 보내지 않는다. 등록 · 삭제는 문장만으로는 일어나지 않고 버튼을 눌러야 한다
- 한 번에 500자 · 초안 20건, 날짜는 오늘부터 30일 전까지. 규칙이 만든 초안이든 OpenAI가 만든 초안이든 **같은 검증기**를 거치고, 저장할 때 서버가 도메인 클래스로 다시 검사한다

| 기능 | 내용 |

| 날짜 읽기 | 오늘 · 어제 · 그저께 · 「3일 전」 · 「11월 20일」 · 「11/20」 · 「지난달 28일」 · 「20일」 |
| 대화로 물어보기 | 기간의 지출 합계 · 카테고리 합계 · 수입 합계 · 그날 목록. 홈 · 달력 · 리포트와 같은 집계를 써서 숫자가 같다. 읽기 전용이고, 미래 기간이나 알아듣지 못한 낱말에는 답하지 않는다 |
| 할 수 있는 일 | 예시 문장 목록. 누르면 입력칸에 채워진다(보내지는 않는다) |

### OpenAI 활용
- **호출:** OpenAI Responses API, 구조화 출력(`json_schema`, strict), `store: false`, 시간 제한 10초. 서버(`OpenAiDraftOrganizer`)에서만 부른다
- **보내는 것:** 규칙이 읽지 못한 문장 조각, 카테고리를 찾지 못한 항목의 내용, 등록한 카드 이름, 오늘 날짜. 문장 전체나 다른 기록은 보내지 않는다
- **받은 것은 믿지 않는다:** 금액 범위 · 날짜 · 구분과 카테고리 일치 · 글자 수를 규칙 초안과 같은 검증기로 검사하고, 카드 이름은 등록된 카드와 같을 때만 남긴다. OpenAI에는 DB · 저장 권한이 없고 저장은 사용자가 눌러야 한다
- **실패해도 멈추지 않는다:** 키 오류 · 요청 제한 · 잔액 소진 · 시간 초과 · 형식 오류 · 하루 상한이면 OpenAI 단계를 건너뛰고 규칙 결과만 쓴다

## 가계부 가이드 `/home/guide`
명세: `docs/spec/91-content.md` · 원고: `src/content/guide/<slug>.md`

질문을 검색하는 사람에게 보이는 것은 소개 페이지가 아니라 그 질문에 답하는 글이라서, 사이트 안에 가이드 글을 둔다. **지금은 게시한 글이 없다** — 첫 원고가 검토 중(`status: draft`)이라 목록과 글 주소 모두 404이고 사이트맵에도 없다.

- **원고:** 머리말(제목 · 설명문 · slug · status · 날짜)이 붙은 마크다운. `published`만 목록 · 사이트맵 · 검색에 나오고 `draft`는 주소로도 열리지 않는다
- **빌드할 때 정적으로 만든다:** Turbopack의 글자 모듈 유형으로 원고를 코드에 묶는다. 새 의존성 없음, 실행 중 파일 읽기 없음(Workers)
- **마크다운 변환:** 직접 만든 작은 변환기(`GuideMarkdown`) — 소제목 · 문단 · 목록 · 굵게 · 링크만 읽고, 그 밖의 문법은 빌드 · 테스트에서 멈춘다. HTML 문자열을 끼워 넣지 않는다
- **글 화면:** 제목 · 날짜 · 본문 · 글 끝 안내 상자(출시 알림 신청 — 신청 위치 `guide`). 모바일 지원
- **검색:** 글마다 Article 구조화 데이터와 자기 주소 canonical, 게시한 글은 사이트맵에 자동 추가
- **확인(로컬 Worker, 2026-11-26):** 초안 글 · 없는 글 · 빈 목록 404, 사이트맵에 초안 없음, 초안 글자가 브라우저용 파일에 없음. 게시 상태로 잠깐 바꿔 본 화면에서 1440 · 390 · 360 가로 넘침 없음, 사이트 안 링크에 UTM 없음, 안내 상자에서 신청하면 `source = guide` 저장
