# 대화로 기록하기

> README에서 옮겨 온 문서다(2026-11-27). 본문의 파일 경로는 저장소 루트 기준이다. 돌아가기: [README](../../README.md)

명세 원본: `docs/spec/80-record-assistant.md`(v2.1) · QA 결과: `docs/spec/71-mvp-qa.md`(Q31~Q51) · 시안: `docs/design/app/`(30~58)

기록 폼은 한 건에 여러 칸을 채워야 한다. **한 문장으로 적으면 기록 초안을 만들어 주고, 사용자는 확인하고 저장만 하면 되게** 해서 입력 마찰을 줄였다. 모바일 앱의 「대화로 기록하기」와 같은 동작이다(웹은 앱의 PC 버전).

## 흐름
1. 패널을 연다 → 오른쪽 패널(너비 440, 뒤 화면을 가리지 않음). 들어가는 길은 여러 개다(명세 80 §3-3)
   - 홈: 오른쪽 위 주 버튼 「대화로 기록하기」 · 제목 아래 한 줄 입력칸(보내면 패널이 열리며 그 문장이 처리된다) · 예시 칩 3개(누르면 바로 보낸다 — 세 문장 모두 규칙만으로 처리돼 OpenAI를 부르지 않는다)
   - 기록하기 폼: 오른쪽 위 「대화로 적기」(적던 값이 있으면 버릴지 먼저 묻는다)
   - 기록 · 달력 · 리포트: 오른쪽 아래 떠 있는 버튼
   - 주소 `/app?chat=1`: 패널을 연 채로 들어온다(소개 사이트의 「웹에서 체험하기」와 「대화로 기록하기」 구역 버튼)
2. 문장을 보낸다 — 「점심 9천원, 커피 4500원」, 「어제 택시 12000원」, 「월급 300만원」
3. 초안 카드가 나온다. 카드를 눌러 고치고(수정 시트), 지출 카드는 왜 썼나요 · 그때 기분을 칩으로 고를 수 있다(선택)
4. 「n건 저장하기」 → 확인 창 → 저장 요약. 문장의 날짜마다 그 날짜로 저장된다

## 문장을 읽는 순서
위에서부터 먼저 맞는 것으로 정한다(모바일 앱과 같은 순서, 테스트로 고정).

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | 도움말 낱말(「도움말」 · 「뭐 할 수 있어」) | 「할 수 있는 일」 목록과 예시 |
| 2 | 「고정지출」 · 「고정수입」 · 「매달」 · 「매월」 | 고정지출 등록 카드 · 목록 · 삭제 확인 |
| 3 | 「○○카드」 + 「등록」 · 「추가」 | 카드 등록 카드 |
| 4 | 금액이 있다 | 기록 초안 |
| 5 | 묻는 말(「이번 달 카페 얼마」 · 「어제 뭐 썼지」) | 저장된 기록에서 센 숫자로 답한다(대화로 물어보기) |
| 6 | 그 외 | 「금액을 찾지 못했어요…」 안내 |

- 4번의 기록은 **규칙 기반 파서**(금액 · 날짜 · 낱말 사전 38개 카테고리 400개 낱말)가 먼저 읽는다. 읽지 못한 조각과, 내용은 있는데 카테고리를 찾지 못한 항목만 OpenAI로 보낸다. OpenAI가 만들거나 채운 카드에는 「AI가 정리」를 붙인다
- 1 ~ 3번과 5번은 규칙으로만 읽고 OpenAI로 보내지 않는다. 등록 · 삭제는 문장만으로는 일어나지 않고 버튼을 눌러야 한다
- 한 번에 500자 · 초안 20건, 날짜는 오늘부터 30일 전까지. 규칙이 만든 초안이든 OpenAI가 만든 초안이든 **같은 검증기**를 거치고, 저장할 때 서버가 도메인 클래스로 다시 검사한다

## 기능
| 기능 | 내용 |
|---|---|
| 자주 적는 항목 | 최근 석 달에 3번 이상 적은 항목을 칩으로 보여 준다. 누르면 초안 카드가 생긴다 |
| 금액만 먼저 적기 | 「4500」만 보내도 카드가 된다. 카테고리가 빈 기록은 다음에 패널을 열 때 「채우지 않은 기록」으로 알려 준다 |
| 고정지출 · 고정수입 | 「넷플릭스 17000원 매달 15일 고정지출」로 등록, 「고정지출 보여줘」로 보기 · 고치기 · 지우기. 나가는 날이 되면 「기록할까요?」라고 묻는다(자동으로 기록하지 않는다) |
| 카드 등록 | 「삼성카드 등록해줘」 → 다음 문장부터 「점심 9천원 삼성카드」의 카드 이름과 결제수단을 채운다 |
| 날짜 읽기 | 오늘 · 어제 · 그저께 · 「3일 전」 · 「11월 20일」 · 「11/20」 · 「지난달 28일」 · 「20일」 |
| 대화로 물어보기 | 기간의 지출 합계 · 카테고리 합계 · 수입 합계 · 그날 목록. 홈 · 달력 · 리포트와 같은 집계를 써서 숫자가 같다. 읽기 전용이고, 미래 기간이나 알아듣지 못한 낱말에는 답하지 않는다 |
| 할 수 있는 일 | 예시 문장 목록. 누르면 입력칸에 채워진다(보내지는 않는다) |

## OpenAI 활용
- **호출:** OpenAI Responses API, 구조화 출력(`json_schema`, strict), `store: false`, 시간 제한 10초. 서버(`OpenAiDraftOrganizer`)에서만 부른다
- **보내는 것:** 규칙이 읽지 못한 문장 조각, 카테고리를 찾지 못한 항목의 내용, 등록한 카드 이름, 오늘 날짜. 문장 전체나 다른 기록은 보내지 않는다
- **받은 것은 믿지 않는다:** 금액 범위 · 날짜 · 구분과 카테고리 일치 · 글자 수를 규칙 초안과 같은 검증기로 검사하고, 카드 이름은 등록된 카드와 같을 때만 남긴다. OpenAI에는 DB · 저장 권한이 없고 저장은 사용자가 눌러야 한다
- **실패해도 멈추지 않는다:** 키 오류 · 요청 제한 · 잔액 소진 · 시간 초과 · 형식 오류 · 하루 상한이면 OpenAI 단계를 건너뛰고 규칙 결과만 쓴다
- **비용:** 호출 1회 약 $0.0002(2026-11-25 측정). 문장 보내기 1분 20회 · OpenAI 호출 1분 6회 · 하루 300회로 막고, OpenAI 프로젝트 지출 한도를 $5로 두었다

## 개인정보
- 입력칸 아래에 늘 「알아듣지 못한 부분은 정리를 위해 OpenAI로 보내요. 이름 · 연락처 같은 개인정보는 적지 마세요.」를 보여 준다
- 문장 · OpenAI 응답 · 대화 내역을 저장하지 않고 로그에도 남기지 않는다(오류 종류와 사용량 숫자만). 패널을 닫으면 대화는 사라진다
- 키 · OpenAI 주소 · 프롬프트 · 낱말 사전은 브라우저 코드에 들어가지 않는다(빌드 결과물 · QA Q43으로 확인)
- 처리방침(`/home/privacy`)에 OpenAI 전송(받는 곳 · 항목 · 목적 · 보유 기간 · 쓰지 않는 방법)을 적었다
