# 소개 사이트 `/home`

> README에서 옮겨 온 문서다(2026-11-27). 본문의 파일 경로는 저장소 루트 기준이다. 돌아가기: [README](../../README.md)

## 서비스 소개
세이블리(Savely)는 직접 적으며 소비를 돌아보는 가계부 앱이다(iOS · Android, 출시 전).
- **문제:** 돌아볼 틈 없이 같은 한 달이 반복된다. 결제는 터치 한 번이면 끝나고, 월말 명세서에서야 합계를 본다
- **해결:** 적고 · 마감하고 · 돌아보는 습관을 만드는 가계부 + 꾸준한 마감을 돕는 세이블리 포인트
- **기대효과:** 점검이 습관이 되면 한 달이 달라진다
- **핵심 행동:** 「출시 알림 신청」 — 이메일을 남기면 출시 소식을 먼저 받는다

### 타깃 (초안)
- 가계부를 써 봤지만 오래 못 간 사람
- 월말 카드값에 놀라는 일이 반복되는 사람
- 가족 소비를 함께 돌아보고 싶은 사람

## 측정과 검색 노출
명세: `docs/spec/90-measurement-search.md` · **구현은 됐고 아직 배포하지 않았다** — 실서비스에는 통계 스크립트가 없다. ID는 들어 있지만 실서비스 주소에서만 보내므로 로컬에서는 아무것도 불러오지 않는다. 배포 전에 남은 일은 명세 §2-7 · §2-8에 있다(방침 문장 확정 · 개정일)

「어떤 메시지와 섹션이 출시 알림 신청으로 이어지는지」를 재기 위한 장치다.

- **도구:** GA4(이벤트). 네이버 애널리틱스(방문 · 유입 경로)는 코드만 두고 꺼 두었다(2026-11-27, 명세 90 §2-9). ID는 `src/lib/analytics/config.ts` 상수 — 비어 있으면 Noop, 값이 있어도 실서비스 주소에서만 보낸다. 쿠키 · 사이트 저장소를 쓸 수 없는 브라우저와 본인 방문 표시(`?sv_internal=1`)가 있는 브라우저에서는 통계 스크립트를 아예 불러오지 않는다
- **구조:** 화면 · 훅은 `AnalyticsPort`만 부른다(`gtag`를 직접 부르지 않는다). 흐름을 이벤트로 옮기는 일은 `HomeFunnel` · `AssistantFunnel`이 하고, 구현체(`GtagAnalytics` · `NaverAnalyticsScript` · `NoopAnalytics`)는 `container.ts`에서 조립한다
- **이벤트:** `section_view`(섹션별 1회) · `waitlist_open` · `generate_lead` · `waitlist_error` · `demo_click`(소개 사이트), `assistant_open` · `assistant_send` · `assistant_save` · `assistant_limit`(체험판)
- **보내지 않는 것:** 이메일, 대화로 적은 문장, 기록 내용 · 금액 · 메모, 카드 이름. 이벤트 유형에 글자를 그대로 싣는 칸이 없다 — 정해진 낱말과 개수만 보낸다
- **개인정보처리방침과 한 묶음:** 측정 ID를 넣는 배포에는 방침의 방문 통계 · 받는 곳(Google) · 쿠키 거부 방법 항목이 함께 있어야 한다. 네이버 ID와 방침의 네이버 문장은 함께 넣고 함께 뺀다(둘 다 테스트가 확인)
- **검색:** 소개 페이지에 Organization · WebSite 구조화 데이터, 사이트맵에 수정일, 제목 · 설명에 검색어 반영
- **확인(로컬, 2026-11-26 ~ 27):** 로컬 주소에서 우리 서버 밖으로 나간 요청 0. 개발 서버의 디버그 표시로 GA4가 이벤트를 받는 것(204)과 요청에 이메일 · 문장 · 금액이 없는 것을 확인. 설치 코드와 대조. 쿠키를 막은 브라우저(전체 차단 · 이 사이트만 차단)와 본인 방문 표시가 있는 브라우저에서 통계 스크립트 · 수집 요청 0건, 신청 창 · 체험판 이동은 정상(Chromium만 확인). /app 화면 이동 때 네이버 페이지뷰를 다시 보내도록 고침(네이버를 켤 때 쓴다). DebugView 화면 · 네이버 실시간 분석 · 구조화 데이터 온라인 검사기는 대표 계정 · 배포 뒤에 확인

## 가계부 가이드 `/home/guide`
명세: `docs/spec/91-content.md` · 원고: `src/content/guide/<slug>.md`

질문을 검색하는 사람에게 보이는 것은 소개 페이지가 아니라 그 질문에 답하는 글이라서, 사이트 안에 가이드 글을 둔다. **지금은 게시한 글이 없다** — 첫 원고가 검토 중(`status: draft`)이라 목록과 글 주소 모두 404이고 사이트맵에도 없다.

- **원고:** 머리말(제목 · 설명문 · slug · status · 날짜)이 붙은 마크다운. `published`만 목록 · 사이트맵 · 검색에 나오고 `draft`는 주소로도 열리지 않는다
- **빌드할 때 정적으로 만든다:** Turbopack의 글자 모듈 유형으로 원고를 코드에 묶는다. 새 의존성 없음, 실행 중 파일 읽기 없음(Workers)
- **마크다운 변환:** 직접 만든 작은 변환기(`GuideMarkdown`) — 소제목 · 문단 · 목록 · 굵게 · 링크만 읽고, 그 밖의 문법은 빌드 · 테스트에서 멈춘다. HTML 문자열을 끼워 넣지 않는다
- **글 화면:** 제목 · 날짜 · 본문 · 글 끝 안내 상자(출시 알림 신청 — 신청 위치 `guide`). 모바일 지원
- **검색:** 글마다 Article 구조화 데이터와 자기 주소 canonical, 게시한 글은 사이트맵에 자동 추가
- **확인(로컬 Worker, 2026-11-26):** 초안 글 · 없는 글 · 빈 목록 404, 사이트맵에 초안 없음, 초안 글자가 브라우저용 파일에 없음. 게시 상태로 잠깐 바꿔 본 화면에서 1440 · 390 · 360 가로 넘침 없음, 사이트 안 링크에 UTM 없음, 안내 상자에서 신청하면 `source = guide` 저장
