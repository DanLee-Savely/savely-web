## 점검 방법 메모
- **Q3 서버 검증:** 브라우저 검사를 통과한 저장 요청(Server Action 본문)을 가로채 금액 0 · 내일 날짜 · 61자로 바꿔 보냈다. 서버가 같은 도메인 클래스로 거부하고 같은 문구를 돌려줬다.
- **Q4 두 번 저장:** 화면이 다시 그려지기 전 같은 순간에 3번 클릭(`button.click()` 3회).
- **Q7 · Q9 사진 파일 삭제:** 로컬 R2 저장 폴더의 객체 수로 확인했다(교체하면 그대로, 삭제하면 1개 줄어듦).
- **Q14 업로드 실패:** 오프라인에서는 요청이 서버에 닿지 않아 E10(저장 실패)이 나온다. 서버에서 R2 업로드만 실패하는 경우(E9, 기록 저장 안 함)는 단위 테스트(`records.test.ts` 「사진 업로드가 실패하면 기록을 저장하지 않는다」)로 확인했다.
- **Q17:** 로딩은 CDP로 응답 지연 1.5초를 걸고 목록으로 이동, 오류는 로컬 D1 표 이름을 잠시 바꿔 조회를 실패시켰다.
- **Q18:** 등록 → 목록 → 수정 화면을 여는 동안 받은 응답(HTML · JS · RSC · 사진) 전체에서 D1 · R2 이름, 데이터베이스 id, 바인딩 이름, R2 공개 주소(`r2.dev` · `r2.cloudflarestorage.com`)를 찾았고 하나도 없었다. **배포 후 소유자 확인:** 대시보드 R2 → `savely-record-images` → Settings에서 Public access(r2.dev) · Custom domain이 꺼져 있는지.
- **Q20:** 서버의 「오늘」은 `Intl.DateTimeFormat('en-CA', { timeZone: 'Asia/Seoul' })`로 계산한다(서버 시간대와 무관). 한국 시간 0~9시 경계(UTC로는 전날)는 시각을 고정한 단위 테스트(`record.test.ts` RecordDate)로 확인했다.
- **Q21:** Cloudflare · 로컬(miniflare) 요청 제한은 **벽시계 1분 단위 고정 창**이다. 분이 바뀌는 순간에 걸치면 짧은 시간에 최대 20회까지 통과할 수 있다(30-waitlist §2의 「지역별 근사치」와 같은 성격). 점검은 분이 시작된 직후에 했다.
