# 20 · 인터랙션 명세

- 출처: Figma 라이트 프로토타입(페이지 `70:2269`)의 컴포넌트 변형과 리액션 설정값
  - 원본 덤프: `docs/figma/interaction-components-light.txt`, `docs/figma/prototype-frames-light.txt`
  - 상태별 이미지: `docs/design/interactions/<세트>/`
- 시간 값은 Figma 설정을 반올림한 값이다(예: 0.8999 → 0.9초).
- 「Figma 동작」은 프로토타입의 실제 설정이고, 「사이트 구현」은 실제 웹에서 만들 동작이다. 둘이 다르면 사이트 구현을 따른다(00-decisions D7).
- **모든 애니메이션 공통 규칙**
  - `prefers-reduced-motion: reduce`이면 자동 재생은 하지 않고 최종 상태만 보여준다. 전환은 즉시 바뀐다.
  - 자동 재생 애니메이션은 섹션이 화면에 들어올 때(IntersectionObserver, 30% 이상 보일 때) 시작하고, 화면에서 벗어나면 멈춘다.
  - 상태 전이 로직은 `src/interaction/`의 순수 클래스(예: `StepSequencer`, `CarouselCursor`, `WaitlistFormFlow`)에 두고, 화면은 그 상태만 그린다(CLAUDE.md §5).

## I1 · 히어로 앱 화면 캐러셀
- **구조:** 휴대폰 화면 안에 5장을 가로로 이어 붙인 track. 현재 번호 × 화면 폭만큼 track을 왼쪽으로 옮긴다.
  - 순서: 홈 → 기록 작성 → 달력 → 하루 상세 → AI 리포트 (content.json `hero.device.screens`)
- **Figma 동작**
  - 다음 버튼 · 화면 탭: 다음 장(SMART_ANIMATE 0.45초, ease-in-out). 5번째에서 다음 → 1번째(DISSOLVE 0.3초)
  - 이전 버튼: 이전 장(0.45초). 1번째에서 이전 → 5번째(DISSOLVE 0.3초)
  - 점 클릭: 해당 장으로 이동. 거리가 3칸 이상이면 DISSOLVE 0.3초, 아니면 슬라이드 0.45초
  - 점: 현재 점은 20×6 `accent`, 나머지는 6×6 `border`, 간격 6, 모서리 3. 위에 현재 화면 이름(Support/13, text-2)
- **사이트 구현**
  - 위 동작을 그대로 구현한다. 슬라이드는 `transform: translateX`, 0.45초 `cubic-bezier(.4,0,.2,1)`. 순환 이동은 0.3초 페이드
  - 모바일 · 터치: 좌우 스와이프로 이전/다음. 가로 이동이 세로 이동보다 크고 40px 이상일 때만 넘긴다(세로 스크롤 방해 금지)
  - 키보드: 캐러셀에 포커스가 있을 때 ←/→로 이동. 버튼에 `aria-label`(「이전 화면」, 「다음 화면」), 점에 「n번째 화면: 이름」
  - 영역에 `aria-roledescription="carousel"`. 현재 화면 이름은 `aria-live="polite"`로 알린다
  - **자동 넘김 없음**(00-decisions D4)
  - 이미지: `next/image`. 첫 장만 `priority`, 나머지는 지연 로딩. 크기 288×640(모바일 203×451) 기준 `sizes` 지정

## I2 · 공감 말풍선 순차 등장
- **Figma 동작** (변형 Step 0 → 3)
  - Step 0: 1번째 자리에 「입력 중」 말풍선(•  •  •, Label/15, text-3)만 보임. 실제 말풍선은 투명
  - 0.8초 후 Step 1: 1번째 말풍선이 나타남 + 2번째 자리에 「입력 중」 (전환 0.35초)
  - 1초 후 Step 2: 2번째 말풍선 + 3번째 「입력 중」 (0.35초)
  - 1초 후 Step 3: 3번째 말풍선까지 모두 보임 (0.35초)
  - 4초 후 처음으로(페이드 0.4초) — 반복
- **사이트 구현:** 화면 진입 시 한 번만 재생하고 Step 3에서 멈춘다(반복하지 않음). 말풍선은 투명도 0→1 + 아래에서 8px 올라옴
- 마지막 문장(「몇 번을 다시 시작해도…」)은 Step 0~2에서 투명하고, Step 3(마지막 말풍선)과 함께 나타난다(0.35초). 2026-10-30 Figma 수정 반영 — 이전에는 처음부터 보였음

## I3 · 문제 흐름 단계 강조 (PC) — 2026-10-30 C안으로 교체
- **동작** (`StepSequencer` · `useStepSequence` 재사용, 한 번 재생)
  - 0~3단계: n번째 열만 불투명도 1, 나머지 열 0.25 (0.9초 간격, 전환 0.35초). 돌아오는 선과 알약의 「↻」 · 글자도 0.25(알약 배경은 그대로)
  - 4단계 「반복」: 모든 열 0.25. 돌아오는 선이 `accent` 2px, 알약 배경 `accent-tint-2` · 글자 `accent` (2.5초 머묾 — Figma `문제 흐름 C` 세트 `111:1329`의 State=5 값)
  - 5단계(최종): 모든 열 · 화살표 1, 선 · 알약 기본 상태로 멈춘다
  - 「→」는 앞뒤 열 중 하나가 활성일 때만 1, 아니면 0.25(4단계에서는 0.25)
- 화면 진입(30%) 시 시작. reduced-motion이면 최종 상태
- **모바일:** 애니메이션 없음(정적).

## I4 · 금융 수치 설명 툴팁
- **Figma 동작:** 수치 블록에 마우스를 올리면(0.2초) 라벨 옆 「ⓘ」와 값이 accent로 바뀌고, 블록 아래 8px(블록 하단 기준)에 툴팁이 나타남
  - 2026-10-29 수치 블록을 박스(`surface` · r16 · pad 24)로 바꿈. 같은 행의 박스는 높이가 같아서(PC 190) 툴팁은 세 블록 모두 상단 기준 +198
  - 툴팁: 폭 320, `surface-3`, r10, pad 12/14, 세로 gap 6. 설명(Support/13, text) + 출처(Support/13, text-3)
- **사이트 구현**
  - PC: hover와 키보드 focus 모두에서 열린다(라벨 행을 `button`으로 만들고 `aria-describedby`로 툴팁 연결)
  - 모바일: 「ⓘ」 탭으로 열고 닫는다. 바깥을 탭하면 닫힌다
  - 문구: content.json `literacy.stats[].tooltip` + `tooltipSource`
- **막대 성장 (2026-10-30 추가):** 수치 막대 · 문제 카드 그래프가 각각 화면에 들어오면(30%) **0.4초 뒤** 막대가 0→값으로 0.8초 ease-out으로 자라고, 값 라벨 · 기준선 라벨이 함께 나타난다. 한 번만 재생
  - Figma: `금융 수치 막대` `108:322` · `문제 카드 그래프` `108:397` 세트(Grow=0 → 0.4초 뒤 Grow=1, SMART_ANIMATE 0.8초). 프로토타입은 4초 뒤 되돌아가 반복하지만 사이트는 한 번만
  - 그래프마다 따로 감지한다(모바일 S04는 2,000px이 넘어 섹션 기준 30%가 화면 안에서 충족되지 않음)
  - CSS `transform: scale`로 그린다(그래프 라이브러리 없음). reduced-motion이면 최종 상태

## I5 · 해결 스텝 전환 (PC)
- **Figma 동작:** 3.5초마다 다음 단계로 자동 전환(0.4초), 3 → 1 순환. 단계 항목을 클릭하면 그 단계로 바로 이동(0.35초)
  - 선택 상태 표시는 10-sections S05 참고. 오른쪽 휴대폰 화면이 단계별 캡처로 바뀜(02 기록 작성 / 03 달력 / 05 리포트)
- **사이트 구현**
  - 화면 진입 시 자동 전환을 시작한다
  - 사용자가 항목을 클릭하면 그 단계로 이동하고 **자동 전환을 멈춘다**(읽는 중 넘어가지 않게)
  - reduced-motion이면 자동 전환 없이 1단계로 시작한다
  - 단계 목록은 `role="tablist"`, 각 항목은 `role="tab"`, 휴대폰 영역은 `role="tabpanel"`
  - 휴대폰 화면 전환은 페이드 0.4초
- **모바일:** 카드 3장을 세로로 나열한다(애니메이션 없음).

## I6 · 보상 고리 순환 강조
- **Figma 동작** (Step 1 → 4)

  - 「포인트 받고」 칩에는 「+P」(Label/13, accent — 강조 시 흰색)가 붙음
  - 간격: 1→2 0.9초, 2→3 0.9초, 3→4 1.4초(포인트 단계에서 조금 더 머묾), 4→1 0.9초. 전환 0.3초
- **사이트 구현:** 화면에 보이는 동안 순환을 계속한다(반복 재생 유지 — 「습관의 반복」을 보여주는 의도). 화면 밖에서는 멈춘다. reduced-motion이면 3단계(「포인트 받고」 강조)로 고정한다(UI 정적 시안과 같은 상태).
- **모바일:** 칩이 2줄로 줄바꿈되는 것 외에는 같다.

  2. **입력됨:** 이메일 칸 테두리 `accent`. 체크박스 `accent` 배경 + 흰 ✓. 버튼 활성

- **사이트 구현** (상태 전이는 `WaitlistFormFlow` 클래스)
