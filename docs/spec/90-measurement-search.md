# 90 · 측정과 검색 노출 (0~1단계) — v1

작성 2026-11-26 · 상태: **§4 문구 · §2-6 개인정보처리방침 문안 대표 승인 (2026-11-26). 배포는 대표 요청 시에만, 측정 코드와 방침 변경은 같은 배포로.**

> **구현 상태 (2026-11-27):** **배포함**(PR #6, §2-10). GA4만 켜져 있고 네이버 애널리틱스는 꺼 두었다(§2-9). Amplitude도 **배포했다**(2026-11-27, PR #10, §2-11). 쿠키 · 사이트 저장소를 쓸 수 없는 브라우저와 본인 방문 표시가 있는 브라우저에서는 통계 스크립트를 불러오지 않는다. 아래 §2-7 ~ §2-9의 「배포하지 않았다」는 그 절을 쓴 때의 상태다.

## 0. 목적과 범위

- 받은 피드백: "출시 알림 전환율처럼 실제 사용자 반응을 측정해, 어떤 메시지와 섹션이 설득에 가장 기여하는지 확인하는 단계로 넘어가 보세요."
- 대표 결정 (2026-11-26)
  - 측정 도구: **GA4 + 네이버 애널리틱스 함께**
  - 목표 검색어: **세이블리 · 가계부 · 앱테크 · AI 가계부 · 직접 쓰는 가계부 · 수기기록 가계부** (각각 검색했을 때 세이블리가 나오는 것)
- 이 문서의 범위
  - 0단계: 측정 장치 (§2)
  - 1단계: 검색엔진 등록과 기술 점검 (§3), 검색어를 담은 문구 제안 (§4)
- 범위 밖: 3단계 검색어별 콘텐츠(대표 결정 대기), 4단계 검색광고(지금은 하지 않음 — 대표 2026-11-26), A/B 테스트, 쿠키 동의 배너

## 1. 검색어별 현재 상태와 판단

현재 소개 페이지 문구(`src/content/home.content.ts`)에 각 표현이 나오는 횟수 (2026-11-26 확인):

| 검색어 | 지금 사이트에 | 판단 | 주요 수단 |
|---|---|---|---|
| 세이블리 | 25회 | 이름이 고유해 가장 먼저 잡을 수 있음 | 등록 · 구조화 데이터 · 공식 채널 |
| 직접 쓰는 가계부 | 0회 ("직접 적으며"는 있음) | 세이블리 핵심 메시지와 같은 말. 구체적인 검색어라 상대적으로 현실적 | 제목 · 설명 · 본문 + 3단계 글 |
| 수기기록 가계부 | 0회 ("수기" 0회) | 위와 같음 | 설명 · 본문 + 3단계 글 |
| AI 가계부 | 0회 ("AI"는 14회) | 대화로 기록하기가 실제 근거. 같은 말을 쓰는 앱이 많을 수 있음 | 본문 + 3단계 글 + 체험판 |
| 가계부 | 5회 | 경쟁이 매우 큰 단어. 소개 페이지 한 장으로는 상위 노출이 어려움 | 4단계 광고가 사실상 유일한 단기 수단 |
| 앱테크 | 0회 | 경쟁이 크고, 검색 의도(돈 버는 앱)와 세이블리(기록 습관 + 마켓이 열리면 바꾸는 포인트)가 어긋남 | 4단계 광고 + 사실에 맞는 문구 |

**모르는 것과 확인 방법**
- 각 검색어의 월 검색량 · 경쟁 정도: 네이버 검색광고 「키워드 도구」, 구글 애즈 「키워드 플래너」로 확인. 둘 다 광고 계정이 필요함.
- 지금 세이블리가 어떤 검색어로 몇 번 노출되는지: §3-1 등록 후 서치어드바이저 · 서치콘솔 보고서에서 확인 (등록 후 데이터가 쌓여야 보임).
- 검색 순위는 검색엔진이 정하므로 어떤 작업도 노출을 보장하지 않음.

**지켜야 할 것**
- 같은 검색어를 억지로 반복하지 않는다. 구글 스팸 정책은 비슷한 검색어로 순위를 얻으려고 만든 중간 페이지를 "doorway abuse"로 규정한다. 검색어마다 내용 없는 페이지를 찍어 내지 않는다 (3단계 글은 실제로 읽을 내용이 있어야 함).
- 「앱테크」를 쓰더라도 기존 문구 규칙(수익 · 현금처럼 · 출금 · 정액 보장 · 투자 등 금지, 포인트는 「마켓이 열리면」)은 그대로 지킨다.

## 2. 측정 (0단계)

### 2-1. 도구별 역할

| 도구 | 보는 것 | 비고 |
|---|---|---|
| GA4 | 섹션 도달, 버튼 클릭, 신청 성공 · 실패, 유입 경로(UTM), 체험판 사용 | §2-3의 이벤트를 받는다 |
| Amplitude (2026-11-27 추가, §2-11) | GA4와 같은 이벤트 + 자동 수집 페이지뷰 · 세션 · 유입 경로 | §2-3의 이벤트를 같은 이름 · 같은 매개변수로 받는다. 네이버 애널리틱스로는 이벤트를 보내지 않는다 |
| 네이버 애널리틱스 | 방문 · 페이지뷰 · 유입 경로 · 네이버 검색어 | 공통 스크립트만 설치. 전환 스크립트(`wcs.cnv`)는 4단계에서 네이버 광고를 할 때만 |
| D1 `waitlist.source` (이미 있음) | 어느 버튼으로 연 창에서 신청이 완료됐는지 (서버 기준 사실) | GA4가 막히는 브라우저(차단 확장 등)에서도 남는 기준값. GA4 수치와 대조용 |

D1 기준값은 지금도 볼 수 있다 (이메일은 출력하지 않음):

```
npx wrangler d1 execute savely-waitlist --remote --command "SELECT source, COUNT(*) AS n FROM waitlist GROUP BY source ORDER BY n DESC"
```

### 2-2. 설치 원칙

1. **ID는 비밀값이 아니다.** GA4 측정 ID(`G-…`)와 네이버 애널리틱스 발급 ID(`wa`)는 페이지 소스에 그대로 보이는 값이다. `src/lib/analytics/config.ts` 상수로 둔다. 값이 비어 있으면 아무것도 보내지 않는다(Noop). → ID를 받기 전에도 구현 · 배포 준비를 할 수 있다.
2. **보내는 곳은 실서비스 주소에서만.** `location.hostname === "www.savelyglobal.com"`일 때만 스크립트를 넣는다. localhost · 미리보기 주소에서는 Noop (개발 중 확인은 GA4 DebugView용 `debug_mode`를 개발 환경에서만 켠다).
3. **구조는 기존 계층을 따른다.**
   - `application`: `AnalyticsPort` 인터페이스 (`track(event)`), 이벤트 타입 정의
   - `infrastructure/analytics`: `GtagAnalytics`(GA4), `NaverAnalyticsScript`(공통 스크립트 로더), `NoopAnalytics`
   - `interaction` · 컴포넌트: 포트만 호출. 컴포넌트가 `gtag`를 직접 부르지 않는다.
4. **보내지 않는 것 (반드시 지킴):** 이메일, 대화로 적은 문장, 기록 내용 · 금액 · 메모, 카드 이름, 검색어 입력값. 주소의 쿼리 문자열은 `utm_*`만 남기고 나머지(`chat=1` 등)는 page_location에서 빼도 된다(선택).
5. **GA4 설정 (대표님 관리 화면 작업, §3-1):** Google 신호 데이터 수집 끔, 광고 개인화 끔, 데이터 보관은 기본값 2개월 유지. 보관 설정은 탐색 분석 · 유입경로 보고서에만 영향을 주고 일반 집계 보고서에는 영향을 주지 않는다(Google 도움말 7667196). GA4는 IP 주소를 기록하거나 저장하지 않는다(Google 도움말 9019185).
6. **대표님 본인 방문 빼기:** `/home?sv_internal=1`로 한 번 들어오면 브라우저에 `sv_internal=1`을 저장하고, 이후 GA4 config에 `traffic_type: "internal"`을 붙인다. 대표님이 GA4 「데이터 필터 → 내부 트래픽」을 켠다. 네이버 애널리틱스에서 본인 방문을 빼는 방법은 확인하지 못함 → 대표님 방문이 섞일 수 있음.
   - **2026-11-27 변경(§2-9):** 표시가 있는 브라우저에서는 통계 스크립트를 아예 불러오지 않는다. `traffic_type`은 더 쓰지 않는다(Google 태그가 스스로 보내는 `page_view`에는 붙지 않아 걸러지지 않았다).
7. **페이지 이동:** /app은 화면 안에서 이동한다. GA4는 「향상된 측정 → 브라우저 기록 이벤트 기반 페이지 변경」으로 잡힌다(기본 켜짐). 네이버 애널리틱스가 화면 안 이동을 잡는지는 확인하지 못함 → 구현 후 「실시간 분석」에서 /app 이동이 잡히는지 확인하고, 안 잡히면 경로가 바뀔 때 `wcs_do()`를 다시 부른다.
8. **성능:** 두 스크립트 모두 `next/script`의 `afterInteractive` 이후로 늦게 불러 첫 화면을 막지 않는다.

### 2-3. 이벤트 목록 (GA4)

이름은 소문자 + 밑줄. 매개변수 값도 소문자.

**소개 사이트 (/home)**

| 이벤트 | 언제 | 매개변수 | 비고 |
|---|---|---|---|
| `section_view` | 섹션이 화면에 50% 이상 처음 보일 때. 페이지당 섹션별 1회 (구현: 섹션의 절반이 화면에 들어왔거나, 화면의 절반을 그 섹션이 채웠을 때 — 화면보다 훨씬 긴 섹션은 앞의 조건을 영영 채우지 못한다) | `section` | 값은 `home.content.ts` 각 섹션의 `id`를 그대로 쓴다 (예: `assistant`, `reward`). id가 없는 섹션은 컴포넌트 이름 기준으로 id를 추가 |
| `waitlist_open` | 신청 창이 열릴 때 | `source`, `last_section` | `source`는 기존 `WaitlistSource` 값(gnb · hero · final-cta · floating · mobile-menu). `last_section`은 열기 직전 마지막으로 본 섹션 — 떠 있는 버튼을 누른 사람이 어느 섹션에서 마음을 정했는지 보기 위함 |
| `generate_lead` | 신청 성공(`result.ok`) | `source`, `last_section` | GA4 권장 이벤트 이름. **핵심 이벤트(key event)로 지정** |
| `waitlist_error` | 신청 실패 | `source`, `code` | `code`는 `WaitlistErrorCode` 그대로 |
| `demo_click` | 체험판 링크 클릭 | `placement` (`hero` · `assistant` · `guide`) | 「웹에서 체험하기」, 「웹 체험판에서 AI 기록 도우미 써 보기」 |

**체험판 (/app)**

| 이벤트 | 언제 | 매개변수 | 비고 |
|---|---|---|---|
| `assistant_open` | 대화 패널이 열릴 때 | `entry` | `deeplink`(`/app?chat=1` — 소개 사이트 버튼) · `home_button`(홈 오른쪽 위 버튼) · `home_composer`(홈 입력칸) · `example_chip`(홈 예시 칩) · `form_button`(기록하기 폼의 「대화로 적기」) · `floating_button`(기록 · 달력 · 리포트의 떠 있는 버튼). 구현(E1~E5)에 맞춰 확정 2026-11-26 — 처음 안의 `other`는 떠 있는 버튼 하나뿐이라 이름을 붙였다. 패널이 이미 열려 있을 때 홈에서 보낸 문장은 여는 것이 아니라 `assistant_send`만 나간다 |
| `assistant_send` | 문장을 보낸 결과가 왔을 때 | `drafts` (만든 초안 수) | 문장 · 금액 보내지 않음. 질문 · 도움말 · 등록 문장과 실패한 문장은 0 |
| `assistant_save` | 초안을 저장할 때 | `count` | |
| `assistant_limit` | 하루 한도 · 요청 제한 안내가 보일 때 | `kind` (`daily` · `rate`) | 한도가 실제로 문제인지 보기 위함. **지금은 `rate`만 나간다** — 「요청이 너무 많아요」가 보일 때(문장 보내기 · 저장 · 등록). 하루 상한(OpenAI 300회)은 화면에 안내가 없어(80 W4 — 결과가 규칙만 쓴 것과 같다) 브라우저가 알 수 없다. 재려면 서버가 알려 줘야 한다 → §6 U4 |

**GA4 관리 화면에서 할 일 (대표님):** 위 매개변수(`section`, `source`, `last_section`, `code`, `placement`, `entry`, `kind`, `drafts`, `count`, 가이드 글의 `guide_slug`)를 「맞춤 정의 → 맞춤 측정기준(이벤트 범위)」으로 등록해야 보고서에 나온다. `generate_lead`를 핵심 이벤트로 표시한다.

### 2-4. 유입 경로 꼬리표 (UTM) 규칙

밖에 거는 모든 링크에 붙인다. 소문자, 단어 사이는 밑줄.

| 항목 | 값 |
|---|---|
| `utm_source` | `naver_blog` · `instagram` · `threads` · `kakao` · `codeit` · `naver`(광고) · `google`(광고) |
| `utm_medium` | `blog` · `social` · `referral` · `cpc`(광고) · `email` |
| `utm_campaign` | `launch_waitlist` (출시 알림 모집 기간 공통) |
| `utm_content` | 글 · 게시물 구분 (예: `2026-12-02_ai_gagyebu`) |

예: `https://www.savelyglobal.com/home?utm_source=naver_blog&utm_medium=blog&utm_campaign=launch_waitlist&utm_content=2026-12-02_ai_gagyebu`

### 2-5. 보는 법 (첫 리포트 기준)

1. **신청률** = `generate_lead` 사용자 수 ÷ /home 방문 사용자 수. 기간 · 유입 경로(소스/매체/캠페인)별로 본다.
2. **섹션 도달률** = 섹션별 `section_view` 사용자 수 ÷ /home 방문 사용자 수. 어디서 많이 이탈하는지 본다.
3. **어느 메시지가 신청으로 이어졌나** = `generate_lead`의 `source` · `last_section` 분포.
4. **체험판 효과** = `demo_click` → `assistant_open(entry=deeplink)` → `assistant_save`로 이어진 비율.
5. **서버 기준 대조** = §2-1의 D1 조회 결과와 GA4 `generate_lead` 수를 비교한다. GA4가 적게 나오는 만큼이 측정이 막힌 몫이다.

해석 주의: 방문자가 적은 동안의 차이는 우연일 수 있다. 몇 주 이상 쌓인 뒤 판단하고, A/B 테스트는 방문이 충분히 늘어난 뒤에 한다.

### 2-6. 개인정보처리방침 변경 (대표 승인 2026-11-26 — 측정 배포와 같은 배포에 반영. 「← 확인 후」 표시 두 곳은 배포 전 확인 필수)

> **2026-11-27:** 네이버 애널리틱스를 꺼 둔 동안에는 아래 문안의 네이버 부분(2번 「· 네이버 애널리틱스」, 5번 받는 곳 ④, 6번 「· 네이버 애널리틱스」)이 방침에서 빠져 있다. 다시 켤 때 되돌린다 → §2-9.

현재 방침 2번에는 "IP 주소 · 기기 정보 · 쿠키는 저장하지 않아요."라고 적혀 있다. 측정 도구를 넣으면 이 문장이 사실과 달라지므로 **측정 코드와 방침 변경을 반드시 같은 배포에 넣는다.**

**확인 1 — 개발 서버 `?sv_ga_debug=1`로 GA4에 이벤트가 들어가는가**

- ⚠️ 이 확인 중 2026-11-26 19:01(한국 시간)에 **디버그 표시 없이** 이벤트 20개가 localhost 주소로 GA4에 들어갔다(표시가 붙지 않는다는 것을 그때 알았다). 보고서에 localhost 방문으로 남는다.

**확인하며 알게 된 것**
1. **`initAll`은 통계 말고도 Amplitude의 다른 제품을 함께 켠다.** Guides and Surveys 스크립트를 `cdn.amplitude.com`에서 내려받아 실행하고 `gs.amplitude.com`(config · decide · state · resource_center)을 부르며, `[Guides-Surveys] Engagement Booted` 이벤트를 보낸다(기기 ID · 페이지 경로 · 쿼리 포함). 끄는 옵션이 없어 `init`으로 바꿨다(대표 결정 3).
2. **`@amplitude/unified` 1.2.9의 `init(키, 설정)`은 설정을 무시한다.** 안에서 상위 `init`을 늘 인자 3개로 불러, 두 번째 인자가 사용자 ID 자리로 들어간다. 그렇게 부른 동안에는 모든 이벤트의 `user_id`에 설정 객체가 실려 나갔고(로컬 확인에서만 — 가로챈 요청이라 Amplitude에는 가지 않았다), 페이지뷰 옵션이 적용되지 않았다. 세 번째 인자로 넘겨 고쳤다. **패키지를 올릴 때 이 동작이 바뀌는지 다시 확인한다.**
3. **SDK 기본값에서는 Amplitude 관리 화면의 자동 수집 설정(원격 설정)이 코드의 설정보다 우선한다.** SDK가 페이지를 열 때 원격 설정을 받아 오고, 거기에 자동 수집 항목이 있으면 코드의 값을 덮어쓴다(확인 때의 응답은 `analyticsSDK: {}` — 덮어쓰는 것 없음). 관리 화면에서 누른 요소 수집을 켜면 코드의 「끔」이 풀리고 방침 2번이 사실과 달라지므로, 원격 설정을 받아 오지 않게 했다(대표 결정 9). **이제 관리 화면의 자동 수집 설정은 이 사이트에 적용되지 않는다.**
4. 화면 안에서 이동한 직후의 페이지뷰는 제목이 비어서 나가는 경우가 있다(제목이 바뀌기 전에 보낸다). 경로는 맞게 들어간다.
5. `default` 프로젝트에는 처음 연동을 확인할 때(설치 안내 기본값 — `initAll` · 자동 수집 전체 · 리플레이 100%) 보낸 localhost 방문이 남아 있다. 그때 `amp events check-ingestion-by-api-key`가 `observed`를 답했다(최근 8시간 안에 프로젝트로 이벤트가 들어왔다는 뜻 — 어떤 이벤트인지, 몇 건인지는 이 확인으로 알 수 없다). 그 뒤의 확인은 모두 요청을 가로채서 했고 Amplitude로 보내지 않았다.
6. 번들: `@amplitude/unified`에는 쓰지 않는 리플레이 · Experiment · Guides and Surveys 코드도 들어 있다(따로 내려받는 묶음 약 440KB, 보내도 되는 방문에서만 받는다). 줄이려면 `@amplitude/analytics-browser`만 쓰도록 바꾼다.

2. **사이트 이름 제약 (알고 진행):** Google은 사이트 이름용 WebSite 구조화 데이터를 도메인 루트(`https://www.savelyglobal.com/`)에서만 읽고, `/home` 같은 하위 경로 홈은 지원하지 않는다고 문서화하고 있다. 지금 루트는 `/home`으로 넘겨 주기만 하므로, 검색 결과 위 사이트 이름이 「세이블리」로 나오지 않을 수 있다. 바꾸려면 루트에서 소개 페이지를 직접 보여 줘야 하고 이는 F8 · 라우트 구조 변경이다 → 이번 범위에서 하지 않고, 노출을 본 뒤 대표님이 결정. (검색 순위와는 별개인 표시 문제)
